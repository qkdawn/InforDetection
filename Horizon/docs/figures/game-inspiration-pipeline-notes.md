# 游戏创意雷达流程图说明

## 图稿契约

- 核心结论：来源策略只定义观察范围，内容本身决定主题板块；候选经评分、证据检索、价值评估与编辑成稿后，被转译为“发生了什么、真正新鲜的关系、可启发的游戏问题”三类设计洞察。
- 图稿类型：`schematic-led composite`。
- 目标输出：183 × 190 mm，白底，整页论文技术路线图语法；中文标题/主题与必要的英文技术术语直接标注。SVG 为主格式，同时导出 PDF、300 dpi PNG 与 600 dpi TIFF。
- 后端：R，使用基础 `grid` 绘图；通过 `rsvg` 和 `png` 载入图标，并以 `svglite`、`ragg` 和 `grDevices` 导出。
- 视觉策略：三栏整页构图；左栏回答“看什么、多久看一次、来源如何治理”，中栏为编号 1–3 的采集、分类评分、筛选去重与重评，右栏为编号 4–6 的证据检索、候选评估/终审/编辑成稿、报告分发。阶段编号和向下箭头形成唯一阅读路径；两层分支总线表达六类内容路由。
- 图标：流程控制节点采用一致的 Lucide 线性图标；来源池、采集、分类评分、六个游戏主题、证据增强、报告组版、概念图与交付节点采用 `gpt-image-2` 生成的科学编辑插画。生成提示词与资产保存在 `docs/figures/generated-icons/`。
- 主证据：n8n 与 Horizon API 的 `/fetch → /score → /filter → /research → /evaluate → /select → /enrich → /report → /feishu` 主链。
- 支撑证据：六个内容板块、各节奏来源规模、来源治理规则、三段设计洞察结构及多模态交付物。
- 完整性说明：本图是系统工作流示意图，不包含抽样数据、统计检验或实验图像调整。

## 节点口径

1. `采集与标准化`：按 Daily、Weekly 或 Reserve 选择来源池，抓取后解析正文、合并相同 URL、执行域名安全检查，并写入统一内容结构。
2. `内容路由与灵感评分`：分类依据标题和正文，而不是账号所属类别。每条内容进入六个主题板之一，并使用对应提示词生成灵感分与理由。
3. `筛选、去重与重评`：应用各板块阈值、板块内语义去重，必要时补取 X 回复并重评分，形成进入研究阶段的候选集；当前 n8n 主链不启用独立的平衡配额。
4. `证据检索与引用`：围绕候选内容补充背景检索，核对来源与主张的对应关系，形成可引用的证据包。
5. `候选评估、终审与设计转译`：先评估设计潜力与证据质量，再选择 10 条、至少覆盖 4 个主题且单一来源最多 2 条，最后生成三段设计洞察；不满足事实、证据或设计价值的候选可被退稿。
6. `多模态报告与分发`：生成完整 Markdown/HTML、封面和逐条概念图，通过 Browserless 渲染为 1080 × 1440 PNG 卡片组，并推送飞书。

## 运行

在 `Horizon` 目录执行：

```powershell
Rscript -e "install.packages(c('svglite', 'ragg', 'rsvg', 'png'), repos='https://cloud.r-project.org')"
Rscript docs/figures/game-inspiration-pipeline.R
```

文件将写入 `docs/figures/generated/`。
