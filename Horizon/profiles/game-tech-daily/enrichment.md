# 游戏创意雷达：enrichment v5

## 任务

从来源中找出值得游戏设计者继续思考的创意线索。日报不负责把材料扩写成完整玩法，而是依次回答：来源明确说了什么；其中哪种具体关系真正新鲜；这段关系可以打开哪一类游戏设计问题。

## 后台推理步骤（不要展示）

1. 分开来源事实与玩法推演，不补写来源没有提供的事实。
2. 从材料中提取一个来源不可替代的关系：谁或什么，在什么条件下，以何种反常方式影响了什么。
3. 去掉来源中的具体关系，检查结论是否仍可套到大量无关材料；如果可以，重新提炼。
4. 把这段关系转成一个开放的游戏设计问题。问题应指出值得探索的玩家处境或设计矛盾，但不要预先给出角色、场景、机制和答案。

## 标题

- 用 10–22 个中文字写出材料中最具体的异常或反差。
- 标题描述创意线索本身，不把它伪装成已经成立的游戏提案，避免“某研究带来的启示”“一个关于选择的游戏”等空泛表达。
- 不夸大来源事实，不用猎奇修辞代替内容。

## Blocks

- `what_happened`: 对应“发生了什么”。用 1–3 句简洁写清原始材料明确提供的具体异常现象，包括必要的主体、条件和结果。这里只写来源事实，不写玩家、关卡或玩法创意；不要为了显得严谨而补写来源通常不会提供的研究方法、样本量、效应量或因果免责声明。
- `fresh_relationship`: 对应“真正新鲜的关系是什么”。用 1–3 句指出材料中最反常、最值得借用的具体联系。这里的关系可以发生在人物、行为、结果、空间、规则、材料、感知或制作方法之间。必须说明关系两端及其连接方式；不复述新闻，不评价它“很有启发”，也不把它抽象成可套用多数材料的通用道理。
- `game_question`: 对应“它可能启发哪一类游戏问题”。提出 1–2 个彼此关联的开放问题，指出设计者可以继续探索的玩家处境、认知矛盾、表达空间或系统难题。问题必须依赖上一栏的具体关系，但不替它设计角色、世界观、行动选项、数值、反馈循环、胜负条件或测试方案。

## 写作要求

- 全文使用普通中文，面向能够讨论玩法体验但不需要阅读论文的游戏策划。
- 三段不得重复：可信现象、新鲜关系、开放的游戏问题各自只承担自己的职责。
- 日报止于提出值得继续设计的问题。不要把问题写成答案，不要提前展开完整玩法或最小原型。
- 不出现 PID、马尔可夫、博弈均衡、状态机、积分项、控制器等后台术语，除非来源本身讨论游戏实现且无法替代。
- 不把所有问题都导向资源条、动态平衡或反复干预。判断、预测、承诺、欺骗与识破、表达与创造、角色扮演、不可靠感知和不可逆后果都可以成为问题方向，但不能机械套用。
- 不虚构来源事实。设计问题用于启发，不代表原作者提出了相应游戏观点。
- 保持来源原有的断言强度：来源只说“相关”就写“相关”，来源只说“可能”就写“可能”。用准确动词完成边界控制，不在段末追加“材料未提供……因此无法确定……”之类的固定免责句。
- 只有缺失信息会实质改变现象含义时，才用一句具体说明；不得照抄或改写后台评分中的常规证据缺口。
- 输出完整、紧凑，可以直接进入日报。
